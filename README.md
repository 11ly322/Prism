## 这是什么

> 一个不啰嗦的看图工具：双击就开，左右键翻页，要调色也够用。
> 只用 Python + Pillow + Tkinter，没有 Electron、没有浏览器内核。

Prism 服务两种场景 ——

| 场景 | 你会用到 |
| :--- | :--- |
| **只想快点看图** | 双击打开、滚轮缩放、左右翻页、胶片条、网格浏览。4000 万像素照片半秒出图——按可见区域渲染，不算看不见的像素 |
| **想做点正经调色** | 曝光对比、高光阴影、色调曲线、8 段 HSL、色调分离、径向与渐变滤镜。全程非破坏式，随时撤销回原图 |

取舍很明确：**不做图库、不做液化、不做 AI 抠图**。只把「看」和「调」做快做稳。

## 人像美化

> 纯算法实现，**不依赖任何模型文件**、不联网、不上传照片。

### 怎么找到它

工具栏「工具 → 人像美化…」，或直接按 `E` 打开面板后点顶部的「人像美化」按钮。
面板顶部常驻一行状态，会告诉你当前情况：

```
人像美化：检出 1 张脸 · 磨皮60 祛斑50 瘦脸20
人像美化：本图不适用（黑白照片）
```

**按住 `B`** 可以临时关闭美颜看效果对比，松开恢复；也可以点「对比(B)」按钮用鼠标切换。

### 九个效果

| 效果 | 范围 | 原理 |
| :--- | :--- | :--- |
| 肤色柔化（磨皮）| 0–100 | 频域分离：只压低频色斑，**高频毛孔原样保留** |
| 磨皮范围 | 0–100 | 模糊半径，越大越均匀 |
| 肤色提亮 | 0–100 | 肤色区提亮，最高 +16% |
| 肤色均匀 | 0–100 | 中值滤波去小斑点 |
| 祛斑 / 痘印 | 0–100 | 大半径背景减除，找出比背景暗的孤立小块并填补 |
| 斑点大小 | 2–15 | 背景估计半径，决定能处理多大的痘印 |
| 眼周提亮 | 0–100 | 眼下区域只提暗部，并压蓝 12% 抵消青紫 |
| 牙齿美白 | 0–100 | 嘴部区域内「亮且中性」的像素去黄提亮 |
| 唇色增强 | 0–100 | 嘴部区域内「红绿差高」的像素加红 |
| 瘦脸 | 0–100 | 下半脸向中线挤压（逆映射重采样）|
| 大眼 | 0–100 | 自动定位最暗的左右两个区域后局部放大 |

另有「人像 · 高级」折叠区：去油光、肤色冷暖、柔光，以及额头/眼周/脸颊/下巴四个分区强度。

### 一键预设

| 预设 | 磨皮 | 祛斑 | 眼周 | 牙齿 | 瘦脸 | 大眼 | 与原图差 |
| :--- | :-: | :-: | :-: | :-: | :-: | :-: | :-: |
| 素颜 | 0 | 0 | 0 | 0 | 0 | 0 | 0.00 |
| 自然 | 35 | 25 | 0 | 20 | 0 | 0 | 0.30 |
| 人像 | 60 | 50 | 35 | 40 | 15 | 15 | 0.94 |
| 网红 | 85 | 70 | 60 | 70 | 45 | 40 | 2.09 |

预设只改美颜参数，不碰曲线 / HSL / 胶片 / 畸变。

### 它怎么找到脸

没有五官关键点模型，用两步近似：

1. **肤色蒙版**：YCbCr 的 Cb 77–130、Cr 132–178
2. **连通域 + 形状校验**：降采样到 160px 宽做标记，只保留宽高比 0.40–1.45、
   填充率 0.30–0.97、面积不小于最大脸 18% 的区域（最多 4 张）

眼睛位置则取脸的上半部里最暗的左右两处，比按固定比例猜准得多。

### 边界与保护

以下情况会**自动跳过**而不是乱涂：图小于 32px、像素不足 4096、长宽比超过 8:1、
肤色占比低于 0.2%、以及**黑白照片**（黑白图色度为 0，会被误判成整张皮肤）。

### 已知局限

- 没有五官关键点，侧脸或低头时效果会减弱甚至跳过（**宁可不动，不乱涂**）
- 导出 12MP 全尺寸时美颜约需 6.5 秒（预览只算可见区域，不受影响）
- 磨皮 25 档几乎不可见，是刻意设计：低档位用于与其它效果叠加

## 插件接口（api 2）

插件就是一个 .py 文件，放在插件目录里，重启 Prism 后出现在「工具 → 插件…」。
目录位置：与 Prism_settings.json 同层（源码运行时是 src/plugins）。

### 契约

~~~python
PLUGIN = {"id": "bw", "name": "黑白", "version": "2.0", "api": 2,
          "author": "Prism"}

PARAMS = [
    {"key": "contrast", "label": "对比增强", "min": 0, "max": 100,
     "default": 20, "step": 5},
]

def run(img, **params):
    from PIL import ImageEnhance
    out = img.convert("L").convert("RGB")
    k = float(params.get("contrast", 20)) / 100.0
    return ImageEnhance.Contrast(out).enhance(1.0 + 0.6 * k)
~~~

| 要点 | 说明 |
| :--- | :--- |
| 签名 | run(img, **params)，返回新的 PIL.Image；**不要原地改 img** |
| 参数 | params 的键就是 PARAMS 的 key，类型已转好（数值 float / 下拉 str / 开关 bool）|
| 控件 | slider（min/max/default/step）· select（options/default）· checkbox（default）· text（default 为字符串）；旧的 range/choice/bool 写法仍兼容 |
| 图像 | 交互预览拿到的是**代理图**（长边 ≤2048），点保存时按**原分辨率**重算；插件内仍建议用 _utils.preview_then_export 自行降采样 |
| 异常 | 直接抛，loader 会捕获、写 logs/plugins.log 并回退原图，主程序不退出 |
| 禁用 | 把 xxx.py 改名 xxx.py.disabled；改回来即启用 |
| 热重载 | **有**。保存后约 1.5 秒自动重载；插件窗口也有「重载插件」按钮 |

api 必须是 2（旧的 1 仍能加载）。版本更高的插件会被跳过并在插件窗口提示，
不会崩溃，也不会静默失败。完整字段与约束见 [docs/plugin-api.md](docs/plugin-api.md)，
提交上游见 [CONTRIBUTING.md](CONTRIBUTING.md)。

### 插件市场 / 从网址安装 / 参数记忆（9.5.0）

- 插件窗口 →「插件市场」：读官方清单 `plugins/index.json`（发布到网页），
  显示「未安装 / 已安装 / 可更新」，一键安装或更新；拉不到清单时用上次缓存，
  窗口里标明「离线缓存」。目前清单有 3 个：渐变减光、柔光、双色调。
- 也可以「从网址安装…」：填 `.py` 的 http(s) 直链，可选填 SHA-256。
  下载后**只解析 AST、不执行代码**，先确认再写盘；单文件上限 2 MB。
- 清单与 README 索引共用一份数据：`tools/make_plugin_index.py` 从
  `plugins/index.json` + 插件源码生成两处表格，`--check` 接进发布门禁。
- 每个插件的参数按 `PLUGIN.id` 自动记住，重启后仍在；「恢复默认」会清空记忆。

### 调试

- 启动参数 --plugin-dev：日志记录每个插件的加载/执行耗时，界面提示「插件 X 执行耗时 Nms」，异常时提示插件名 + 异常类型 + 首行。
- 日志格式：[时间] plugin=<id> api=<n> <load|run> failed: <类型>: <首行>，写在 logs/plugins.log。
- 插件可声明 network / writes_files 两个能力字段，插件窗口会显示出来。

### 内存估算口径

单张图的内存估算（`ImageDoc.mem_bytes()`）= 解码后像素字节 +
**文件本身的字节数**。8.3.6 起非 RAW 不再把整个文件读进内存，
文件大小改由 `file_bytes`（os.path.getsize）记录，所以估算值不变，
但**常驻内存少了一整份文件**（40MP JPEG 可省 18~30MB）。

### bench 测试图

`tools/bench.py` 默认生成一张「低频块 + 高频噪声」的真实感 4000 万像素图（约 18MB）。
早期用纯色图（0.6MB、解码 30ms），解码与内存类优化在基准里体现不出来，已废弃。

## 外观与排版

界面在 8.5 系列做了一轮系统性整理，目标是「看起来不糙」，而不是换皮：

- **设计令牌**：间距统一为 4 的倍数（`SPACE_XXS`…`SPACE_3XL`），
  字号为 11 / 12 / 13 / 15 / 18 五档（`FONT_XS`…`FONT_XL`），
  圆角半径 `RADIUS_SM/MD/LG`。散落的魔法数字收敛到文件头部。
- **层级靠明度**：面板底 `#141414`、分区卡片 `#1c1c1c`，
  用明度差和 6px 外距分层，不用边框也不用色块。
- **圆角按钮**：`_QpeRoundButton` 是 Canvas 自绘控件（平滑多边形画圆角矩形），
  带 normal / hover / disabled 三态。面板 70 余处按钮与工具栏按钮统一使用。
- **对齐**：分区标题与滑杆内容对齐到同一列（实测差 1px），
  数值固定 6 字符宽，右边缘成一列。
- **开关有状态**：工具栏「面板」按钮在侧栏打开时高亮，不再看不出开/关。
- **插件列表两列**：12 个插件按两列卡片排布，信息密度与可读性平衡。

## 性能基准

测试机：**AMD Ryzen 7 H 255（Radeon 780M）· 19.8 GB RAM · Windows 11 26200 · Python 3.12.14**。
数字用 python tools/bench.py 可复现，同一台机器连跑三次取中位数。

| 项目 | 8.3.0 | 8.3.1 | 8.3.2 / 9.3.0 |
| :--- | ---: | ---: | ---: |
| 启动到可交互 | 1677 ms | 1583 ms | **1530 ms** |
| **4000 万像素首帧** | 759 ms | 777 ms | **223~425 ms（< 1 秒）**，真实 18MB 图、3 轮标准差 2~30 ms |
| 滑杆预览延迟 | 77 ms | 80 ms | **77 ms** |
| 代理图生成（主线程）| 183 ms | 189 ms | **1 ms** |
| 内存（当前 / 峰值）| 154 / 241 MB | 155 / 242 MB | **179 / 211 MB** |
| 胶片条缩略图缓存 | 无上限 | 24 张 LRU | 24 张 LRU |

| 2 核限流 · proxy 3400（5 轮）| — | — | 首帧 1677±123 ms · 滑杆 267±29 ms · 峰值 227 MB |
| 2 核限流 · proxy 2800（5 轮）| — | — | 首帧 1782±125 ms · 滑杆 229±29 ms · 峰值 206 MB |

**代理上限 A/B 结论（2 核绑定、5 轮、标准差已标注）**：2800 与 3400 在首帧与滑杆上
**没有显著差异**（区间重叠），唯一可复现的收益是内存峰值 227 → 206 MB（−9%）。
因此**不调整默认值 3400**；内存吃紧的用户用 `--low-mem`（2048）或 `--proxy 2048`。
别拿「更小代理一定更快」当结论 —— 实测否掉了。


数据由 python tools/bench.py --repeat 3 取得，三轮取中位数，每轮独立子进程
（同进程连跑会让 Tk 资源累积、内存虚高 60% 以上）。


代理图长边可用 --proxy N 调整（512~6000），优先级 --proxy > --low-mem(2048) > 默认 3400；
预览、插件代理与 plugins/_utils.preview_then_export 共用同一套上限。

解码路径（同一台机器，tools/bench.py 实测）：

| 路径 | 耗时 | 输出 | Mpx/s |
| :--- | ---: | ---: | ---: |
| open + draft 到 1600 + load | 24 ms | 2000×1250 | 105 |
| open + 全量 load | 105 ms | 8000×5000 | 382 |
| reduce(4) + resize 1600 | 94 ms | 1600×1000 | 17 |
| 单步 resize 1600 | 409 ms | 1600×1000 | 3.9 |

原始数据见 tools/bench-results.json（含机器配置与版本号，可追加多轮对比）。

### 低内存模式

菜单「视图 → 低内存模式」，或命令行 --low-mem。开启后：

- 代理图长边从 3400 降到 **2048**（内存与缩放耗时都下降）
- 瓦片缓存从 3 张减到 2 张
- 参数保存在 Prism_settings.json


> **关于「首帧 < 1 秒」**：8.3.8 起这条重新成立，且有真实数据支撑 ——
> 两段式加载（大图先出 2000x1250 预览）实测 223 ms、标准差 2 ms；
> 单段解码 425 ms。两者都 < 1 秒；前者更快但有「糊→清晰」的跳变，
> 当前版本按用户反馈选择单段（无跳变）。

### 性能档位

启动参数 `--perf-profile`，按用途在「首帧快」与「拖动快」之间选：

| 档位 | 首帧 | 拖动 | 适合 |
| :--- | ---: | ---: | :--- |
| **fast-slider**（默认） | 632 ms | **75 ms** | 边看边调，最常用 |
| fast-first | **346 ms** | 181 ms | 只想快速翻图 |
| auto | 346~632 ms | 75~181 ms | 让程序按图大小自己选 |

（实测数据：真实 18MB / 4000 万像素、2 核限制、3 轮中位。）

后缀可强制 PhotoImage 更新方式：`--perf-profile fast-first-new`、
`--perf-profile fast-slider-paste`。不加后缀时按核数自动（≤4 核用 paste）。

配套参数：

- `--proxy N`：代理图长边（默认 3400，低内存 2048）
- `--low-mem`：低内存模式
- `PRISM_DEBUG_DECODE=1`：把每次解码的请求尺寸与实际解出尺寸写进 logs/plugins.log

### 代理图与导出

**调色预览走代理图，导出走原图。** 预览时按屏幕可见区域与代理分辨率计算，
所以拖滑杆只要几十毫秒；保存/导出时用原始分辨率从头算一遍，
美颜、细节、暗角、水印都是全质量的。两者用同一套算法与参数，
不会出现「预览好看、导出不一样」（tools/beautycheck.py 里有逐像素校验）。

## 已知情况

> 下载区正下方也有三行摘要：未签名 / 全屏为兼容模式 / macOS 与 Linux 为源码预览。

- macOS 与 Linux 版本为**源码运行包**，只在 Windows 上验证过，界面细节可能有差异。
- 安装包未做代码签名，Windows SmartScreen 可能提示「未知发布者」。
- 「打开所在文件夹」依赖 Windows 的 `os.startfile`，在 macOS / Linux 上无动作。
- **全屏功能已于 9.3.0 移除**（F11 全屏存在显示不全的问题，权衡后直接去掉）。
