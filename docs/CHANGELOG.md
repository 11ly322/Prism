# Prism 变更记录

> 说明：本软件早期名为 QPE，后更名为 Prism。为保持统一，历史条目中的产品名
> 已一并改为 Prism，功能与时间线不变。代码里的 QPEApp / _QpeSlider 等内部
> 标识符与旧配置迁移路径保持原名，改动会破坏兼容。

## v9.15.5  （右侧修图栏重排：固定工作区 + 分层调整）

- **右侧栏重新排版**：顶部固定标题、直方图和四个快捷入口，下方调整分区滚动；
  直方图不再随长面板滚走。
- **固定底栏**：撤销 / 重做 / 对比 / 保存常驻面板底部，长面板滚动时仍可操作。
- **分区层级**：分组标题改为粗体卡片头，保留折叠/展开；基本、镜头、曲线、
  HSL、细节、效果、局部、预设、快照沿纵向阅读。
- **工具与历史**：批量、改名、分屏、胶片条、网格、排序、文件夹、自动色调、
  过曝警告、锁定取色、设置、粘贴设置收进「工具」折叠区，默认收起；
  历史记录也随该区收纳，主滚动区只留调整内容。
- **宽度与滚动条**：默认面板 260px（旧默认 238px 自动迁移），可继续拖宽；
  系统 Scrollbar 换成随主题自绘的细滚动条，浅色主题不再出现白色槽。
- **保留**：现有快捷键、主题/描边、裁剪、局部滤镜、预设/快照、大屏版布局不变。
- 回归：`runall --fast` 20 套全过，外观截图基线更新；版本最后一位 4 → 5。

## v9.15.4  （主题与排版 20 轮：可开关动效 + 点击反馈）

  工具条矢量图标按下反色；设置/插件/菜单、大屏底栏、裁剪比例按钮补按下色；
  滑块按下显示主题色圆环；均为 90–130ms 短反馈，不改变布局尺寸。
- **主题反馈**：主题网格新增 3px 选中竖条，选中主题文字用强调色；
  切主题后标记即时跟随；主题行有独立 hover 态。
- **排版**：设置窗口 450×600，动效卡片与主题/描边同区，主题行距加大；
  动效卡片使用卡片底色与结构描边，保持高对比模式下的层次。
- **验证**：新增 `tools/motioncheck.py`（默认值、持久化、按钮/图标/原生反馈、
  主题标记、状态渐变、关闭后立即响应），`runall --fast` 20 套全过；
  20 轮明细见 `design/iteration-9.15.4.md`。
- 版本号最后一位 3 → 4；网站/三语文案同步。

## v9.15.0  （描边改为独立开关，高对比风格）

  懒加载的面板、语言切换后重建的工具条、新打开的设置窗口都会补上描边。

## v9.14.1  （主题预览色块不再随切换变色）

- 设置里的主题预览色块（每套 5 个颜色样本）之前会被 `_swap_colors` 当成普通控件：
  切换主题时，任何「底色等于旧主题色」的样本都会被替换，结果所有行的预览都变成
  当前主题的颜色，无法再比较。
- 现在给预览色块打 `_theme_preview` 标记，主题重着色时整块跳过；它们始终显示
  `THEMES` 里的静态样本色。
- `tools/themecheck.py` 新增：11 套 × 5 = 55 个预览色块，浅色/深色/新主题循环切换后
  颜色必须逐字节保持不变。
- `runall --fast` 18 套全过；设置界面与 9.14.0 外观一致，仅预览色块不再被误改。

## v9.11.1  （批量渲染也移入后台）

- 9.11.0 只把解码/保存放进 worker，渲染仍在主线程；本版把**渲染也移到后台**：
  为每张图复制一个轻量渲染副本（独立缓存、不共享 Tk 状态），worker 里跑
  `_flatten` 后直接保存，主线程只更新进度。
- 批量导出时界面全程可操作，不再有大图渲染那一下卡顿；渲染结果与主线程
  `flatten_doc` 一致（同一套管线，只换执行线程）。
- `tools/batchcheck.py` 增加曝光、暗角、水印、美颜用例，3 张图仍全部成功、尺寸正确。
- 无调色算法变化；软打样/全分辨率计时沿用 9.11.0。

## v9.11.0  （批量异步 + 全分辨率计时 + ICC 软打样）

### 批量导出异步化

- 每张图的 **解码** 与 **保存** 移到后台线程，渲染仍回主线程（渲染管线会临时借用 app 状态，
  不能并发）；主线程在等待期间持续刷新进度、窗口不冻结。
- 进度分两段显示「正在解码 / 正在保存」，成功/失败计数实时更新；取消仍按“当前这张做完就停”。
- 新增 `tools/batchcheck.py`：3 张图批量导出、主线程事件泵、输出尺寸、成功计数，5 项断言。

### 全分辨率载入计时

- 载入期间状态栏按钮显示「载入中 1.3s…」，每 0.5 秒刷新；Esc 取消、切图会自动停表。
- 完成/失败/取消都会清掉计时任务，不会残留 after 回调。

### ICC 软打样（预览）

- 设置 → 软打样：选择目标 ICC（如印刷 profile），预览按
  `sRGB → 目标 profile → sRGB` 双变换显示，模拟印刷后的色域压缩。
- **只影响预览，不影响导出**；导出仍统一 sRGB。设置与 profile 路径持久化。
- 支持系统 `.icc/.icm`；没有 ImageCms 的 Pillow 构建会提示并保持关闭。
- 新增 `tools/softproofcheck.py`：真实 AdobeRGB 双变换、sRGB 恒等、输出尺寸/模式；
  uicheck 增加启用/关闭与设置界面断言。

### 验证

## v5.3

- **一次综合性能体检**（画布 1764×1396 ≈ 2.5 MP）：

  | 项目 | 耗时 |
  | --- | --- |
  | 渲染 · 无调整 | 18.7 ms |
  | **渲染 · 全套调色（拖动帧）** | **109.2 ms** ← 唯一有量级的问题 |
  | 渲染 · 全套调色（精修首帧） | 113.6 ms |
  | 缩放 | 0.3–0.4 ms |

  | 直方图 + 曲线联动 | 35.1 ms |

  问题在于**拖动帧几乎不比精修帧便宜**（109 vs 114）—— 颜色管线本身变贵了，
  `fast` 只是跳过了细节项。109 ms 意味着拖动时约 9 fps，手感明显滞后。

- **优化：拖动帧降半分辨率渲染。** 画面超过 1.2 MP 时，`fast` 路径先把图缩一半、
  在**小图上走完整的精确调色**、再放大回去。颜色开销与像素数成正比，理论上是 1/4。
  任何异常都直接退回全分辨率（宁可慢也不能错）。

  | | 之前 | 现在 |
  | --- | --- | --- |
  | 拖动帧 | 109.2 ms | **69.4 ms（1.6×）** |
  | 精修帧 | 113.6 ms | 105.9 ms（基本不变）|

  **如实说明**：只拿到 1.6 倍而不是理论上的 4 倍 —— 因为 `_render` 里还有瓦片缩放、
  表面转换、暗角/水印等固定开销，颜色管线只占其中一部分。代价是拖动过程中画面会临时
  变软（松手后 160 ms 内的精修帧恢复全分辨率，导出永远是全分辨率）。
  实测 800×600 这类小图**完全不触发**这条路径，快慢两条路径结果最大差 0。

  末位再下移——都安全无操作。用「饱和度 ±100」这类滤镜测顺序对画面的影响只有 0.13，
  因为去饱和不可逆，这属于测试样本选得不敏感，不代表顺序无效。）

## v2.7

- **优化：暗角应用提速 2.2 倍。** 原来每次都要 `Brightness.enhance()` 造一张整幅中间图、
  再 `composite` 一次，3.1MP 上 **32.8 ms**。压暗在数学上等价于「乘以一张中心 255、
  边缘 f×255 的乘数图」，改用 `ImageChops.multiply` 单次 C 运算后降到 **15.0 ms**。
  实测与旧实现**最大差 1、平均差 0.06**（纯舍入），亮角仍走原路径、逐像素完全一致。
- 修一处我自己的推导错误：乘数 LUT 方向写反（掩膜是「中心 0、边缘 255」），会导致
  **中心被压暗、边缘不动**——整个暗角正好反过来。对照旧实现才发现（最大差 168）。

## v2.6

- **优化：水印绘制只合成文字区域。** 原先每帧都造一张**整幅**透明层再 alpha_composite，
  3.1MP 上要 25 ms。现在只画一小块文字贴片，用 `alpha_composite(patch, dest)` 局部合成，
  **25.3 → 15.5 ms**，九个「位置 × 大小 × 浓度」组合与旧实现**逐像素一致**（最大差 0）。
- 修一处自己引入的坐标 bug：贴左下/左上角时贴片左上角是负坐标，被 `max(0, ...)` 夹住会让
  文字整体偏移（实测左下角三种组合最大差 40–199）。改为裁掉贴片超出画面的那部分、
  合成位置同步归零后才完全对齐。

## v2.5

- **优化：过曝/欠曝警告叠加提速 5.6 倍。** 先实测了一轮渲染各阶段耗时，发现这个仅用于提示
  的叠加层单次要 **168 ms**，比整条调色管线（58 ms）还慢。原因是用 numpy 对整幅 3.1MP
  数组做 max/min、拷贝、再布尔索引赋值。改为全走 PIL 的 C 实现（LUT + 通道极值 +
  带掩膜粘贴），并用 `getbbox()` 把粘贴限制在**真正被裁切的区域**：

  | 场景 | 之前 | 现在 |
  | --- | --- | --- |
  | 局部有过曝（最常见） | 171.7 ms | **30.5 ms** |
  | 整幅全过曝（最坏） | 182.4 ms | **39.6 ms** |
  | 无裁切 | 114.2 ms | **25.0 ms** |

  六组图像（全黑/全白/中间调/局部裁切/随机噪声/渐变）与旧实现**逐像素一致**。
