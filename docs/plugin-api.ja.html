プラグイン API（api = 2）

最小プラグイン

PLUGIN = {"id": "bw", "name": "黑白", "version": "2.0", "api": 2,
          "author": "Prism", "description": "转黑白"}


def run(img, **params):
    return img.convert("L").convert("RGB")

シグネチャ

def run(img, **params) -> PIL.Image

渡されなかったキーは default で補われます。

  • img：PIL.Image。RGB / RGBA / L のいずれかです。その場で変更しないでください。
  • params：キーは PARAMS の key で、値は型に応じて変換済みです（slider=float、select=str、checkbox=bool）。
  • 戻り値：新しい PIL.Image です。サイズもモードも変更できます。
  • メインスレッドで呼び出されます。sleep、ネットワークリクエスト、スレッドの開始は行わないでください。
  • 例外はそのまま送出してください。loader が捕捉してログを書き込み、元の画像にフォールバックします。本体はクラッシュしません。例外を握りつぶして None を返さないでください。

画像契約（重要）

シナリオrun が受け取るもの
プラグインの初回実行プロキシ画像：現在の画像にすべての調整を適用した結果で、長辺は 2048 以下（小さい画像は縮小しない）
結果ウィンドウでパラメータをドラッグ同じプロキシ画像で、変更のたびに再計算されます
「名前を付けて保存…」をクリック元の解像度でパイプライン全体を再計算し、現在のパラメータでプラグインをもう一度実行します

したがって：

  • プレビューは常に秒単位で終わり、40MP の画像でも固まりません。書き出し結果とプレビューは同じパラメータを使うため、見たままが得られます。
  • それでも、プラグイン内で独自にダウンサンプリングすることをお勧めします。プロキシ画像の上限は 2048 ですが、2048 の画像を毎回ピクセル単位で処理するとスライダーが重くなります。次の書き方をそのまま使えます：
  import os, sys
  sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
  from _utils import preview_then_export

  def run(img, **params):
      def work(small):
          return small.convert("L").convert("RGB")
      return preview_then_export(work, img)
  • preview_then_export は、ダウンサンプリング、元のサイズへの拡大、RGBA の alpha の貼り戻しを自身で処理します。
  • 手動で制御したい場合は downscale_if_needed / upscale_back を使ってください。ロジックは上記と同じです。

PARAMS フィールド

フィールド必須説明
keyはいパラメータ名。run の kwargs のキーでもあります
labelはい画面のラベル。文字列または {zh,en,ja}（9.6.0）
typeいいえslider（デフォルト）/ select / checkbox / text
min / maxslider では必須値の範囲
stepいいえステップ幅。デフォルトは 1
defaultはいデフォルト値
optionsselect では必須選択肢のリスト（旧 choices にも対応）。要素は文字列または {value,label} で、label は三言語可
defaulttext文字列。空文字列も可

3 種類のコントロール：

PARAMS = [
    {"key": "amount", "label": "强度", "type": "slider",
     "min": 0, "max": 100, "default": 60, "step": 5},
    {"key": "mode", "label": "风格", "type": "select",
     "options": ["原样", "偏暖", "偏冷"], "default": "偏暖"},
    {"key": "vignette", "label": "加暗角", "type": "checkbox", "default": False},
    {"key": "caption", "label": "说明文字", "type": "text", "default": ""},
]

後方互換：type を省略するか range と書くと slider と同じです。type=choice + choices は select、 type=bool は checkbox と同じです。古いプラグインは変更不要です。text は 8.3.0 で追加され、値は 文字列です。

PLUGIN フィールド

フィールド必須説明
idはい一意の識別子。小文字・数字・-・_ で、_ で始められません（インストール時のファイル名にも使用）
nameはい表示名。文字列または {zh,en,ja}
versionはいプラグイン自身のバージョン
apiはいインターフェースバージョン。現在は 2 である必要があります
authorはい作者
description推奨プラグインウィンドウに表示される 1 行の説明。文字列または {zh,en,ja}
network任意機能宣言：ネットワークを使うかどうか（デフォルト False）
writes_files任意機能宣言：ファイルを書き込むかどうか（デフォルト False）

三言語テキスト（9.6.0）

name / description / PARAMS.label は文字列のほか、 {"zh": "...", "en": "...", "ja": "..."} の形でも書けます。現在の言語が無い場合は 中国語にフォールバックします。文字列だけを書いたサードパーティ製プラグインはそのまま表示されます。 options を {value, label} で書くと、画面には label を表示し、run() には value が渡されます。 文字列だけの場合は値そのものが表示されます。

network / writes_files はプラグインウィンドウに表示され、透明性を高めるためだけのものです。 強制力のある制約ではありません —— プラグインは引き続き完全な権限で動作します。

パラメータの記憶（9.4.0）

Prism は PLUGIN.id ごとに、各プラグインが最後に使ったパラメータを記憶し、Prism_settings.json の plugin_params に保存します。再起動後も残り、次に同じプラグインを実行すると自動的に復元 されます。

  • 範囲外の古い値は新しい min/max にクランプされます。
  • 削除された選択肢は新しい default にフォールバックします。
  • id を変えると別のプラグイン扱いになり、古いパラメータは適用されません。
  • 結果ウィンドウの「初期値に戻す」で、このプラグインの記憶が消去されます。

このためにプラグイン側でコードを書く必要はありません。PARAMS で宣言したデフォルト値は、初回 実行時の値のままです。

URL からインストール（9.4.0）

プラグインウィンドウ →「URL からインストール…」：.py の http(s) 直リンクを入力し、任意で SHA-256 も入力します。

です。 api は対応範囲内である必要があります。 して初めてプラグインディレクトリに書き込まれます。 のファイルが既にある場合は、上書きするかどうかをもう一度確認します。

  1. バックグラウンドスレッドでダウンロードします。単一ファイルの上限は 2 MB、タイムアウトは 15 秒
  2. AST のみを解析し、コードは実行しません：PLUGIN のリテラル辞書と run() が必要で、
  3. SHA-256 を入力した場合は必ず照合します。一致しなければそのまま拒否します。
  4. 確認ダイアログ（名前 / バージョン / 作者 / ネットワーク / ファイル書き込み）が表示され、確認
  5. ファイル名は PLUGIN.id をサニタイズしたもの（ASCII 英数字と - _ のみを残す）です。同名

そのため id には小文字・数字・-・_ のみを使うことをお勧めします。ログ上の識別子と、 インストール後のファイル名の両方になるためです。 SHA-256 はファイルが改変されていないことだけを示し、作者が信頼できることまでは示しません。 インストール前にはご自身で判断してください。

エラーログの形式

logs/plugins.log（Prism_settings.json と同じ階層）に統一して書き込まれます：

[2026-10-18 14:02:11] plugin=skin_smooth api=2 run failed: ValueError: 参数 '强度' 超出范围 (got 120, max 100)

フィールドの順序：時刻、プラグイン id、api バージョン、フェーズ（load / run / reload）、例外の 種類、先頭行の情報。--plugin-dev では完全な traceback も追加で出力されます。
