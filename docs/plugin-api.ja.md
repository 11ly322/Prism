# プラグイン API（api = 2）

## 最小プラグイン

~~~python
PLUGIN = {"id": "bw", "name": "黑白", "version": "2.0", "api": 2,
          "author": "Prism", "description": "转黑白"}


def run(img, **params):
    return img.convert("L").convert("RGB")
~~~

## シグネチャ

~~~python
def run(img, **params) -> PIL.Image
~~~

- img：PIL.Image。RGB / RGBA / L のいずれかです。**その場で変更しないでください**。
- params：キーは PARAMS の key で、値は型に応じて変換済みです（slider=float、select=str、checkbox=bool）。
  渡されなかったキーは default で補われます。
- 戻り値：新しい PIL.Image です。サイズもモードも変更できます。
- メインスレッドで呼び出されます。sleep、ネットワークリクエスト、スレッドの開始は行わないでください。
- 例外はそのまま送出してください。loader が捕捉してログを書き込み、元の画像にフォールバックします。本体はクラッシュしません。**例外を握りつぶして None を返さないでください**。

## 画像契約（重要）

| シナリオ | run が受け取るもの |
| :--- | :--- |
| プラグインの初回実行 | **プロキシ画像**：現在の画像にすべての調整を適用した結果で、長辺は 2048 以下（小さい画像は縮小しない）|
| 結果ウィンドウでパラメータをドラッグ | 同じプロキシ画像で、変更のたびに再計算されます |
| 「名前を付けて保存…」をクリック | **元の解像度**でパイプライン全体を再計算し、現在のパラメータでプラグインをもう一度実行します |

したがって：

- プレビューは常に秒単位で終わり、40MP の画像でも固まりません。書き出し結果とプレビューは同じパラメータを使うため、見たままが得られます。
- それでも、プラグイン内で独自にダウンサンプリングすることをお勧めします。プロキシ画像の上限は 2048 ですが、2048 の画像を毎回ピクセル単位で処理するとスライダーが重くなります。次の書き方をそのまま使えます：
  ~~~python
  import os, sys
  sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
  from _utils import preview_then_export

  def run(img, **params):
      def work(small):
          return small.convert("L").convert("RGB")
      return preview_then_export(work, img)
  ~~~
- preview_then_export は、ダウンサンプリング、元のサイズへの拡大、RGBA の alpha の貼り戻しを自身で処理します。
- 手動で制御したい場合は downscale_if_needed / upscale_back を使ってください。ロジックは上記と同じです。

## PARAMS フィールド

| フィールド | 必須 | 説明 |
| :--- | :--- | :--- |
| key | はい | パラメータ名。run の kwargs のキーでもあります |
| label | はい | 画面のラベル。文字列または {zh,en,ja}（9.6.0） |
| type | いいえ | slider（デフォルト）/ select / checkbox / text |
| min / max | slider では必須 | 値の範囲 |
| step | いいえ | ステップ幅。デフォルトは 1 |
| default | はい | デフォルト値 |
| options | select では必須 | 選択肢のリスト（旧 choices にも対応）|
| default | text | 文字列。空文字列も可 |

3 種類のコントロール：

~~~python
PARAMS = [
    {"key": "amount", "label": "强度", "type": "slider",
     "min": 0, "max": 100, "default": 60, "step": 5},
    {"key": "mode", "label": "风格", "type": "select",
     "options": ["原样", "偏暖", "偏冷"], "default": "偏暖"},
    {"key": "vignette", "label": "加暗角", "type": "checkbox", "default": False},
    {"key": "caption", "label": "说明文字", "type": "text", "default": ""},
]
~~~

後方互換：type を省略するか range と書くと slider と同じです。type=choice + choices は select、
type=bool は checkbox と同じです。古いプラグインは変更不要です。text は 8.3.0 で追加され、値は
文字列です。

## PLUGIN フィールド

| フィールド | 必須 | 説明 |
| :--- | :--- | :--- |
| id | はい | 一意の識別子。小文字・数字・`-`・`_` で、`_` で始められません（インストール時のファイル名にも使用） |
| name | はい | 表示名。文字列または {zh,en,ja} |
| version | はい | プラグイン自身のバージョン |
| api | はい | インターフェースバージョン。現在は 2 である必要があります |
| author | はい | 作者 |
| description | 推奨 | プラグインウィンドウに表示される 1 行の説明。文字列または {zh,en,ja} |
| network | 任意 | 機能宣言：ネットワークを使うかどうか（デフォルト False）|
| writes_files | 任意 | 機能宣言：ファイルを書き込むかどうか（デフォルト False）|

### 三言語テキスト（9.6.0）

`name` / `description` / `PARAMS.label` は文字列のほか、
`{"zh": "...", "en": "...", "ja": "..."}` の形でも書けます。現在の言語が無い場合は
中国語にフォールバックします。文字列だけを書いたサードパーティ製プラグインはそのまま表示されます。
`options` の値は `run()` にそのまま渡され、翻訳されません（表示される値がそのまま選択値です）。


network / writes_files はプラグインウィンドウに表示され、透明性を高めるためだけのものです。
**強制力のある制約ではありません** —— プラグインは引き続き完全な権限で動作します。

## パラメータの記憶（9.4.0）

Prism は PLUGIN.id ごとに、各プラグインが最後に使ったパラメータを記憶し、`Prism_settings.json`
の `plugin_params` に保存します。再起動後も残り、次に同じプラグインを実行すると自動的に復元
されます。

- 範囲外の古い値は新しい min/max にクランプされます。
- 削除された選択肢は新しい default にフォールバックします。
- id を変えると別のプラグイン扱いになり、古いパラメータは適用されません。
- 結果ウィンドウの「初期値に戻す」で、このプラグインの記憶が消去されます。

このためにプラグイン側でコードを書く必要はありません。PARAMS で宣言したデフォルト値は、初回
実行時の値のままです。

## インストールと配布

### プラグインマーケット（9.5.0）

プラグインウィンドウ →「プラグインマーケット」：一覧は公式カタログ `plugins/index.json` から
取得され、「インストール済み / 更新可能 / 未インストール」を確認できます。ボタンを押すとその
ままインストールまたは更新できます。

- カタログ URL のデフォルトは `https://11ly322.github.io/Prism/plugins/index.json` です。環境変数
  `PRISM_PLUGIN_CATALOG` で独自のカタログ（自前のマーケット / イントラネットミラー / テスト）を
  指定できます。
- カタログの取得に失敗した場合は、前回取得に成功したときのキャッシュ（`plugin_catalog.json`、
  設定ファイルと同じディレクトリ）が自動的に使われ、ウィンドウに「オフラインキャッシュ」と表示
  されます。
- インストール／更新の流れは「URL からインストール…」と完全に同じです：ダウンロード → AST のみ
  解析 → SHA-256 を検証 → 確認 → ディスクに書き込み。更新は元のファイル名に書き戻すため、同じ
  id が 2 つできることはありません。
- カタログの `version` は「更新可能」の判定に使います。数値のセグメントごとに比較します
  （`1.10 > 1.9`）。

カタログ形式（schema 1）：

~~~json
{
  "schema": 1,
  "updated": "2026-10-19",
  "homepage": "https://11ly322.github.io/Prism/",
  "plugins": [
    {
      "id": "grad-nd",
      "name": {"zh": "渐变减光", "en": "Grad ND", "ja": "グラデ ND"},
      "version": "1.0",
      "api": 2,
      "author": "Prism",
      "description": {"zh": "…", "en": "…", "ja": "…"},
      "network": false,
      "writes_files": false,
      "url": "https://11ly322.github.io/Prism/plugins/demo-grad-nd.py",
      "sha256": "cf8552bd0a4393e5a798582c00970b2981d6a7f8e14182c682c2eabe666e54ee",
      "source": "docs/plugins/demo-grad-nd.py"
    }
  ]
}
~~~

- `name` / `description` は 3 言語のうち少なくとも zh が必要です。現在の言語がない場合は中国語
  にフォールバックします。
- `url` は http(s) である必要があり、ファイル名は `source` と一致していなければなりません。
  `sha256` はソースとバイト単位で一致している必要があります。
- `source` はリポジトリ内の検証と README の生成にのみ使われ、アプリは読みません。
- リポジトリ内では `plugins/index.json` が唯一のデータソースです。
  `tools/make_plugin_index.py` がこれを検証し、`plugins/README.ja.md` の 2 つの表を生成して、
  `docs/plugins/index.json` にコピーします。リリースゲートでは `make_plugin_index.py --check` を
  実行します。

### URL からインストール（9.4.0）

プラグインウィンドウ →「URL からインストール…」：`.py` の http(s) 直リンクを入力し、任意で
SHA-256 も入力します。

1. バックグラウンドスレッドでダウンロードします。単一ファイルの上限は 2 MB、タイムアウトは 15 秒
   です。
2. **AST のみを解析し、コードは実行しません**：`PLUGIN` のリテラル辞書と `run()` が必要で、
   `api` は対応範囲内である必要があります。
3. SHA-256 を入力した場合は必ず照合します。一致しなければそのまま拒否します。
4. 確認ダイアログ（名前 / バージョン / 作者 / ネットワーク / ファイル書き込み）が表示され、確認
   して初めてプラグインディレクトリに書き込まれます。
5. ファイル名は `PLUGIN.id` をサニタイズしたもの（ASCII 英数字と `-` `_` のみを残す）です。同名
   のファイルが既にある場合は、上書きするかどうかをもう一度確認します。

そのため `id` には小文字・数字・`-`・`_` のみを使うことをお勧めします。ログ上の識別子と、
インストール後のファイル名の両方になるためです。
SHA-256 はファイルが改変されていないことだけを示し、作者が信頼できることまでは示しません。
インストール前にはご自身で判断してください。

## ホットリロードと開発モード

- ホットリロードはデフォルトで有効です。プラグインディレクトリの mtime を 1.5 秒ごとに確認し、
  変更があれば再読み込みしてプラグインウィンドウを更新します。プラグインウィンドウの
  「再読み込み」ボタンから手動で実行することもできます。
- 起動オプション --plugin-dev：ログに各プラグインの読み込み時間と実行時間が記録され、画面に
  「プラグイン X の実行時間 Nms」と表示されます。例外時はプラグイン名 + 例外の種類 + 先頭行の
  情報を表示します。

## エラーログの形式

logs/plugins.log（Prism_settings.json と同じ階層）に統一して書き込まれます：

~~~
[2026-10-18 14:02:11] plugin=skin_smooth api=2 run failed: ValueError: 参数 '强度' 超出范围 (got 120, max 100)
~~~

フィールドの順序：時刻、プラグイン id、api バージョン、フェーズ（load / run / reload）、例外の
種類、先頭行の情報。--plugin-dev では完全な traceback も追加で出力されます。

## バージョン互換性の方針

- API は**追加のみで変更はしません**。新しいフィールドや新しいコントロール種別を追加できます
  が、既存フィールドの意味は変わりません。
- 破壊的変更では**メジャーバージョン**（api 3）を上げ、api 2 は少なくとも 1 リリースサイクル
  維持します。
- Prism は、api が自身の対応範囲内にあるプラグインだけを読み込みます。それより高いものは
  スキップされ、プラグインウィンドウに「プラグイン X は API N が必要ですが、現在は M です」と
  表示されます。クラッシュせず、traceback も出力されません。

## 有効化 / 無効化

plugin.py を plugin.py.disabled にリネームすると無効になり、元に戻すと有効になります。プラグイン
ウィンドウには無効化された項目が一覧表示されます。

## ハード制約

- ネットワークを使わない：デフォルトではネットワークリクエストを発行してはならず、ユーザーの
  画像をアップロードしてはなりません。本当にネットワークが必要なプラグインは PLUGIN.network に
  正しく宣言する必要があり、インストール確認ダイアログにその宣言が表示されます。
- 元の画像のパス以外にファイルを書き込まない（ログは Prism 自身が書き込みます）。ファイルを
  書き込む必要があるプラグインは PLUGIN.writes_files に正しく宣言する必要があります。
- ユーザーが許可していないディレクトリを読み取らない。
- 呼び出し元が渡した img オブジェクトを変更しない。

## 同梱プラグイン

12 個のプラグインの id・パラメータ・ソースは plugins/README.ja.md を参照してください。テンプレート
は plugins/_template.py、小ツールは plugins/_utils.py です。インストール例のプラグイン grad-nd の
