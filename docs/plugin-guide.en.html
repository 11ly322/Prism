Installing plugins

Three ways, same result:

  1. Plugin marketplace (9.5.0): plugin window → "Plugin marketplace" → pick one → "Install" / "Update".
  2. Install from URL: plugin window → "Install from URL…" → enter a direct http(s) link to the .py; you can also enter a SHA-256.
  3. Drop into the folder: put the .py into the plugin folder (the plugin window shows the full path at the top), then click "Rescan" or wait 1.5 seconds for hot reload.

Temporarily disable: rename xxx.py to xxx.py.disabled, and the plugin window shows an "Enable xxx" button.

Installation only guarantees that what was downloaded has not been modified (SHA-256); it does not guarantee that the author is trustworthy. The network / writes_files a plugin declares are shown in the confirmation dialog, but they are only declarations the author filled in.

Publishing a plugin to the marketplace

The official marketplace reads plugins/index.json. From writing a plugin to users seeing it in the marketplace, there are six steps:

In PLUGIN, id must be unique and api must be 2; fill in network / writes_files truthfully; for PARAMS use slider / select / checkbox / text. starting with --plugin-dev lets you see load/run times in logs/plugins.log.

  1. Write the plugin: put the single file in docs/plugins/<filename>.py, using an ASCII filename.
  2. Test locally: put the .py into the plugin folder (the plugin window shows the full path at the top), run it, tune parameters, and save the result;
  3. Compute the SHA-256 (must match the file byte for byte):
   Get-FileHash docs\plugins\myplugin.py -Algorithm SHA256
  1. Add an entry to plugins/index.json (plugins array, schema 1):
   {
     "id": "myplugin",
     "name": {"zh": "我的插件", "en": "My plugin", "ja": "マイプラグイン"},
     "version": "1.0",
     "api": 2,
     "author": "你的名字",
     "description": {"zh": "一句话说明", "en": "One line", "ja": "ひとこと"},
     "network": false,
     "writes_files": false,
     "url": "https://11ly322.github.io/Prism/plugins/myplugin.py",
     "sha256": "<上一步的 64 位小写十六进制>",
     "source": "docs/plugins/myplugin.py"
   }

The filename in url must match source; the official catalog always uses the Pages address.

  1. Generate the index and self-check:
   python tools/make_plugin_index.py          # update the README tables in all three languages + the docs copy
   python tools/make_plugin_index.py --check  # must pass

It validates the SHA-256, the trilingual fields, id uniqueness, api and the URL, and confirms that docs/plugins/index.json matches the repository version. The release gate also runs this step. docs/plugins/index.json together. After merging, the Pages deployment takes effect in about 1 minute; click "Refresh" in the app to see the new plugin, and users with an older version installed will see "Update available".

  1. Open a PR: commit the source, plugins/index.json, plugins/README.md (three files, one per language) and

Updating a published plugin: edit the source in docs/plugins/ → bump the version by 1 (keep PLUGIN.version and the version in index.json in sync) → recompute the SHA-256 → run the generator script. The marketplace decides whether an update is available by version number.

Maintaining your own marketplace (outside the official repository):

  • Put an index.json in the same format on any static http(s) host (every entry must still carry a SHA-256);
  • users set the environment variable PRISM_PLUGIN_CATALOG to point at it before starting Prism;
  • no code changes and no repackaging are needed.

Security bottom line: the catalog itself executes no code; on install the app only parses the AST and strictly compares the SHA-256, and writes to disk only after you confirm.

Parameters are remembered (9.4.0)

Each plugin's parameters are stored in the settings file by id (plugin_params). The next time the same plugin runs, the previous values are restored automatically, including after restarting Prism. Clicking "Restore defaults" in the result window clears this memory.

  • The plugin changes a parameter range: out-of-range values are clamped to the new range.
  • The plugin removes an option: the now-invalid option falls back to the new default.
  • The plugin changes its id: it counts as a new plugin, and the old memory is not applied.

Development workflow

  1. Copy _template.py to myplugin.py (do not start the filename with an underscore; that is reserved for framework files)
  2. Change PLUGIN / PARAMS / run
  3. Save; Prism hot-reloads automatically in about 1.5 seconds (you can also click "Reload plugins" in the plugin window)
  4. Errors do not crash the main app: they are written to logs/plugins.log and the app falls back to the original image
