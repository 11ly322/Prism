# Prism プラグインインデックス

同梱プラグイン 12 個 + 公式のインストール可能なカタログ 1 つ。カタログ `index.json` はアプリ内の「プラグインマーケット」の
データソースも兼ねています。以下の 2 つの表は `tools/make_plugin_index.py` が**プラグインのソース + index.json** から生成します。
表の中身は手で編集しないでください（変更後はスクリプトを 1 回実行するか、`--check` で最新かどうかを確認してください）。

## プラグインをインストールする

方法は 3 つで、結果は同じです：

1. **プラグインマーケット**（9.5.0）：プラグインウィンドウ →「プラグインマーケット」→ 1 つ選ぶ →「インストール」/「更新」。
2. **URL からインストール**：プラグインウィンドウ →「URL からインストール…」→ `.py` の http(s) 直リンクを入力します。SHA-256 も入力できます。
3. **フォルダに入れる**：`.py` をプラグインフォルダ（プラグインウィンドウの上部にフルパスが表示されます）に入れ、「再スキャン」を押すか 1.5 秒のホットリロードを待ちます。

一時的な無効化：`xxx.py` を `xxx.py.disabled` にリネームすると、プラグインウィンドウに「xxx を有効化」ボタンが表示されます。

インストールが解決するのは「ダウンロードしたものが改ざんされていないこと」（SHA-256）だけで、**作者が信頼できるかどうかは解決しません**。
プラグインが宣言する `network` / `writes_files` は確認ダイアログに表示されますが、それは作者自身が記入した宣言にすぎません。

## プラグインをマーケットに公開する

公式マーケットは `plugins/index.json` を読みます。プラグインを書いてからユーザーがマーケットで見られるようになるまで、全部で 6 ステップです：

1. **プラグインを書く**：単一ファイルを `docs/plugins/<ファイル名>.py` に置き、ファイル名は ASCII にします。
   `PLUGIN` では `id` を一意にし、`api: 2` とし、`network` / `writes_files` は事実どおりに記入します。
   `PARAMS` には `slider` / `select` / `checkbox` / `text` を使います。
2. **ローカルで自己テスト**：`.py` をプラグインフォルダ（プラグインウィンドウの上部にフルパスがあります）に入れ、実行し、パラメータを調整し、保存します。
   `--plugin-dev` 付きで起動すると、`logs/plugins.log` の読み込み・実行時間を確認できます。
3. **SHA-256 を計算**（ファイルとバイト単位で一致している必要があります）：
   ~~~powershell
   Get-FileHash docs\plugins\myplugin.py -Algorithm SHA256
   ~~~
4. **`plugins/index.json` に項目を追加**（`plugins` 配列、schema 1）：

   ~~~json
   {
     "id": "myplugin",
     "name": {"zh": "我的插件", "en": "My plugin", "ja": "マイプラグイン"},
     "version": "1.0",
     "api": 2,
     "author": "你的名字",
     "description": {"zh": "一句话说明", "en": "One line", "ja": "ひとこと"},
     "network": false,
     "writes_files": false,
     "url": "https://11ly322.github.io/Prism/plugins/myplugin.py",
     "sha256": "<上一步的 64 位小写十六进制>",
     "source": "docs/plugins/myplugin.py"
   }
   ~~~

   `url` のファイル名は `source` と一致している必要があります。公式カタログは Pages のアドレスを固定で使います。
5. **インデックスを生成して自己チェック**：

   ~~~bash
   python tools/make_plugin_index.py          # README の三言語の表 + docs のコピーを更新
   python tools/make_plugin_index.py --check  # 必ず通すこと
   ~~~

   SHA-256、三言語のフィールド、id の一意性、api と URL を検証し、`docs/plugins/index.json` がリポジトリの版と一致していることを
   確認します。リリースゲートでもこのステップを実行します。
6. **PR を出す**：ソース、`plugins/index.json`、`plugins/README.md`（三言語で 3 ファイル）、`docs/plugins/index.json` を
   まとめてコミットします。マージ後、Pages のデプロイは約 1 分で反映されます。
   アプリで「再取得」を押すと新しいプラグインが表示され、旧バージョンをインストール済みのユーザーには「更新あり」が表示されます。

公開済みプラグインを更新する場合：`docs/plugins/` のソースを変更 → バージョン番号を +1（`PLUGIN.version` と `index.json` の `version` を
同時に更新）→ SHA-256 を再計算 → 生成スクリプトを実行します。マーケットはバージョン番号で更新可否を判断します。

**独自のマーケットを自分で運用する（公式リポジトリに入れない場合）**：

- 同じ形式の `index.json` を任意の http(s) 静的ホスティングに置きます（各エントリには引き続き SHA-256 が必要です）。
- ユーザーは**Prism を起動する前に**環境変数 `PRISM_PLUGIN_CATALOG` をそのカタログに向けて設定します。
- コードの変更も再パッケージも不要です。

セキュリティの最低ライン：カタログ自体は一切のコードを実行しません。インストール時は AST を解析するだけで、SHA-256 を必ず照合し、
確認してから初めてディスクに書き込みます。

## パラメータは記憶される（9.4.0）

各プラグインのパラメータは `id` ごとに設定ファイル（`plugin_params`）に保存されます。次に同じプラグインを実行すると前回の値が自動的に復元され、
Prism を再起動した後も同様です。結果ウィンドウの「初期値に戻す」を押すと、この記憶は消去されます。

- プラグインがパラメータの範囲を変更した場合：範囲外の値は新しい範囲にクランプされます。
- プラグインが選択肢を削除した場合：無効になった選択肢は新しい既定値にフォールバックします。
- プラグインが `id` を変更した場合：新しいプラグインと見なされ、古い記憶は適用されません。

## 開発フロー

1. `_template.py` を `myplugin.py` にコピーします（ファイル名をアンダースコアで始めないでください。それはフレームワーク用ファイルに予約されています）
2. `PLUGIN` / `PARAMS` / `run` を変更します
3. 保存すると Prism が約 1.5 秒で自動的にリロードします（プラグインウィンドウで「再読み込み」を押すこともできます）
4. エラーが発生してもメインアプリはクラッシュしません：`logs/plugins.log` に書き込まれ、元画像にフォールバックします

## 3 種類のコントロール

| type | 必須フィールド | run に渡される型 | 旧記法（引き続き互換） |
| --- | --- | --- | --- |
| slider | min / max / default、任意で step | float | type を省略するか range と書く |
| select | options / default | str | type=choice + choices |
| checkbox | default | bool | type=bool |
| text | default（空文字列可） | str | なし（8.3.0 で追加） |

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| id | はい | 一意の識別子。パラメータの記憶、インストール時のファイル名、マーケットのカタログで使われます。ASCII の英数字と `-` `_` を推奨 |
| name | はい | 一覧に表示される名前 |

## サードパーティ製プラグインの入れ方

- 単一ファイルで、依存は Pillow と numpy のみ（Prism に同梱）。スレッドを起動せず、Prism の内部状態を変更しないでください。
- ファイル名は ASCII、`id` は一意にしてください。`_` で始めないでください。
- 自分のプラグインはユーザープラグインフォルダ（プラグインウィンドウの上部にフルパスがあります）に置いてください。インストールディレクトリ内の同梱プラグインは変更しないでください。
- 公式カタログに収録したい場合：PR を出して `plugins/index.json` に項目を追加し、ソースを `docs/plugins/` に置き、
  `source`、`url`、`sha256` と zh/en/ja 三言語の名前・説明を補完します。`make_plugin_index.py --check` が通る必要があります。
- ネットワーク / ファイル書き込みの副作用があるプラグインは、`PLUGIN` で事実どおりに宣言する必要があります。

## 再利用できる関数

`_utils.py` は `preview_then_export` / `downscale_if_needed` / `upscale_back` / `preserve_alpha` /
`split_alpha` / `to_rgb` / `clamp_params` を提供しています。フレームワークではないので、コピーして使っても構いません。
`preview_then_export(func, img)` が一番手軽です：ダウンサンプリング → func を実行 → 元のサイズに拡大 → alpha を貼り戻す。
インポート前にプラグインフォルダを `sys.path` に追加する必要があります（そのファイル先頭のコメントを参照してください）。
